# 设计模式、动画和玩法模式

已接入项目 `E:\unity\Template`。本次以经典 **23 种 GoF 设计模式**为清单，全部提供实现；对象池、空对象和事件订阅管理作为额外工具保留。

新增通用工具在 `Assets/Scripts/Core/Patterns`，不引用业务层。游戏接入在 Framework / Gameplay / Managers / UI 各自的程序集内。事件广播使用 EventBus；需要一个明确返回值的局部请求使用 Mediator；同一实体的组件可直接组合。各模式独立使用，没有额外全局服务定位器。

菜单 **Guisha → Patterns → Run Examples** 可运行覆盖新增模式的组合示例，代码位于 `Samples/PatternExamples.cs`。

## Mono 单例

```csharp
public sealed class QuestManager : MonoSingleton<QuestManager>
{
    protected override void Awake()
    {
        base.Awake();
        if (!IsPrimaryInstance) return;
        // 初始化与订阅。
    }
    protected override void OnDestroy()
    {
        // 清理自己的订阅和资源。
        base.OnDestroy();
    }
}
```

`MonoSingleton<T>` **继承 MonoBehaviour**，支持 Awake 初始化、重复实例销毁、DontDestroyOnLoad、父节点分离、销毁清理。提供 `Instance`、`Exists`、`TryGetInstance(out instance)`、`RequireInstance()`。默认跨场景，覆盖 `PersistAcrossScenes` 可设置为场景内单例。派生类覆盖 Unity 生命周期时必须调用 base。

每个单例放独立根对象，因为重复实例会销毁其 GameObject。Instance 不隐式创建管理器；现有 GameBootstrap 在场景加载前显式创建管理器。纯 C# 服务使用 PureSingleton，避免为无 Unity 生命周期的服务创建 GameObject。Mono 相关方法从 Unity 主线程调用。

## 动画模块

- `Framework/Animation/AnimationSettings`：参数名、动作状态名和淡入淡出配置资产。
- `IAnimationDriver`：统一 Play / Float / Bool / Trigger。
- `AnimatorDriver` 与 `LegacyAnimationDriver`：Animator 和旧 Animation 两种适配；没有组件时使用 NullAnimationDriver。Legacy 只提供片段播放/淡入淡出，参数式移动应使用 Animator。
- `Gameplay/Animation/EntityAnimator`：玩家/NPC/鬼怪共用桥接组件。自动更新移动速度、蹲伏、落地、死亡参数，监听受击、死亡、攻击与交互事件。
- `AnimationLoggingDecorator`：可选动作日志。参数哈希由享元缓存共享。

演示资产位于 **Assets/GuishaDemo/Animation**，包含 Settings.asset 和 Entity.controller。控制器提供 Idle、Walk、Run、Crouch、Attack、Hit、Dead、Interact。灰盒通过胶囊子节点位移/旋转演示动作切换，正式角色请替换为自己的骨骼动画与 Avatar。

参数约定：Speed(float，世界速度)、Crouched/Grounded/Dead(bool)、Attack/Hit/Interact(trigger)。速度阈值与状态转换在 Animator Controller 中配置。缺失参数或状态会安全忽略；更换 controller 后驱动会更新参数缓存。死亡时切换为 UnscaledTime，让 GameOver 冻结玩法后仍能播完死亡动作；读档恢复原更新模式。

```csharp
EventBus.Publish(new EntityAnimationRequested(entity, EntityAnimationState.Attack));
```

给新角色挂 EntityAnimator，绑定 AnimationSettings 与模型子节点的 Animator。Animator 应放视觉模型子节点，保持 CharacterController / NavMeshAgent 对角色根节点的位置控制。Timeline 和独立过场仍由 CutscenePlayer 管理。

## 四种玩法模式

游戏中按 **M**，或在暂停菜单点“玩法模式”。当前模式、挑战剩余时间或生存波次显示在 HUD。

| 模式 | 默认行为 |
|---|---|
| 剧情 | 伤害 0.75、San 消耗 0.7、体力消耗 0.8、鬼怪速度 0.9，允许存档 |
| 探索 | 玩家免伤、无环境 San / 体力消耗，鬼怪停止敌对 AI，允许存档 |
| 限时挑战 | 副本计时 180 秒，伤害 1.25、San 消耗 1.5、体力消耗 1.2、鬼怪速度 1.15，禁用保存 |
| 无尽生存 | 副本持续刷出增援，波次提高鬼怪速度/伤害，禁用保存 |

挑战模式默认在副本中成功启动任意机关即完成，并返回剧情模式，广播 ChallengeCompleted。可在 Challenge.asset 的 objectiveMechanismId 指定目标机关；超时则 GameOver，可读取此前的剧情/探索存档。主场景不计时、不刷生存波次。模式切换保留当前角色状态，探索不会自动补满此前失去的生命或 San。

每个模式独立的 ScriptableObject 位于 **Config/Modes**，Catalog 由 FrameworkSettings.gameModes 引用；默认启动模式在 FrameworkSettings.defaultGameMode 中配置。GameModeManager 作为 Mono 单例常驻。GameModeRuntime 提供只读规则和进度。存档继续保持 version 1，新增字段有默认值，可读取原来的存档。

SurvivalDirector 的默认间隔为 30 秒，自身生成的活动鬼怪最多 8 个；它不接管关卡预先放置的怪物。生成失败会归还待处理配额，切换模式/停用场景会清理本 Director 的实例，加载晚到的实例按代次丢弃。演示中所有模式共用灰盒地图，正式关卡目标与波次编排可继续扩展。

## 机关与伤害接入

Mechanism.conditionExpression 支持 `线索ID && (!锁定ID || 钥匙ID)`，符号查询 WorldState，支持 true / false / ! / && / || / 括号；旧 requiredClueId 可继续使用，两个条件同时满足才启动。解析出错会阻止交互并提示配置问题。

可在实体根节点挂 DamagePipeline，配置 invulnerable、flatReduction、multiplier。伤害先应用玩法模式的玩家伤害倍率，再执行本地减伤链；没有组件时沿用基础处理。模块互不依赖具体玩家类型。

## 使用边界

- 通用模式工具是主线程工具；PureSingleton 的 Lazy 初始化具有线程安全性，Unity API 始终只在主线程调用。
- CommandHistory 只在命令成功执行后提交历史；命令抛异常时须保证自身未提交副作用。CompositeCommand 会反向撤销已完成子命令，但外部系统回滚仍由子命令实现。每次操作创建新的有状态命令实例。
- Prototype / Memento 的深拷贝由传入的 clone 函数定义。ScriptablePrototype 生成运行时 Unity 对象，由调用方 Destroy；其引用的其他 Unity 资产仍按 Unity 克隆规则共享。
- FlyweightCache 用于不可变元数据，不管理 Addressables 资源引用；资源继续由 ResourceManager 的 lease 管理。Proxy 的资源所有权与释放函数需要明确。
- 模式库没有额外付费包依赖。首次导入后，可运行 **Guisha → Setup Modes And Animation Demo** 为已有灰盒补配置；本项目已完成配置，无需重跑。
