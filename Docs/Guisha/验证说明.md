# 验证说明

本次环境没有安装 Unity 编辑器，因此没有执行 Unity 的真实脚本导入、场景 Play Mode、Addressables 内容构建或 Player 构建。

本地验证使用 Roslyn C# 9 编译器与独立的 Unity API 桩，按实际 asmdef 依赖逐个编译七个程序集，检查 C# 语法、代码内部类型和程序集引用边界。API 桩不能验证真实 Unity API、包程序集名称、序列化与运行生命周期；它不属于交付的 Assets，也不会导入用户工程。

本地还执行实际 Core / Framework 代码的 12 项回归检查，覆盖：独立订阅 token、派发中退订/新增订阅、重入、异常隔离、Clear、生存周期、池复用、非法归还、引用身份、容量与 Dispose、FSM 转换与重入保护。Unity 工程内可用 Test Runner → EditMode 执行对应的 12 个测试；需安装 Unity Test Framework。

## Unity 内验收

1. 安装依赖并导入，确认 Console 无编译错误，运行 EditMode 测试。
2. 生成灰盒，Play，检查移动、跑步耗体力、停止后恢复、蹲伏以及头顶有障碍时不能站起。
3. 转动镜头靠近墙面，确认相机不穿墙；隔着墙不能交互；准星命中后才显示提示。
4. 拾取鬼器、打开背包并使用，验证事件更新快捷栏和 San。
5. 阅读纸条、启动机关、开关门，绿色方块保存。消耗鬼器后 F9，应恢复背包、San、生命、位置、纸条/机关/解锁/拾取标记。
6. 和 NPC 对话，测试空格继续、数字分支；暂停/继续、背包开关、读取存档后确认输入锁释放。
7. 进入两个副本再返回主场景，确认只有一个玩家、相机、EventSystem、AudioListener 在工作，UI 面板正确注册；切换期间不允许重复切换。
8. 鬼怪在烘焙或运行时生成的 NavMesh 上测试：视觉被墙遮挡、跑步声调查、追击、近距离攻击、丢失后返回。死亡后 F9 恢复。
9. 给 PlaySoundRequested/BgmRequested 指定真实音频，验证池归还、距离衰减、遮挡层和淡入淡出。
10. 在 Addressables Profiler 中观察加载/释放，检查正常销毁、场景卸载、失败地址和取消路径。构建 Addressables 内容后再构建桌面 Player。

需要在实际项目检验的边界：自定义模型与碰撞、中文字体、动态门导航、渲染管线、Timeline 相机、平台存储、关闭 Domain Reload 后重复进入 Play Mode，以及 Addressables 版本差异。它们不由本地 API 桩编译证明。
